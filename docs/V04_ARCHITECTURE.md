# v0.4 architecture and evidence boundaries

The frozen v0.3 did not preserve stdout or exact return code for a failed provider subprocess. Consequently the historical NLP assessment failure has no retrospectively provable backend cause. A failing real-process regression reproduces this diagnostic loss, not the unknowable historical service condition. v0.4 persists streams and process metadata before checking success. Auth, quota, request-size and transient-service explanations remain hypotheses unless directly evidenced.

The primary runtime contract is a single source-root argument. No course flag or folder convention affects routing. The corpus inventory is complete within explicitly documented per-source parsing/resource/access limits. Every extracted character appears in a source-hashed segment and SQLite/FTS index. Bounded transport batches do not mean excluded course content. Competencies and methods are derived per batch, with cross-unit FTS retrieval and a global coverage ledger. Retrieval ranking never substitutes for processing all primary segments.

Role checkpoints bind canonical request data, provider identity, image content hashes and result bytes. JSON ordering does not invalidate an unchanged request. Failed/partial checkpoints, original response streams and prior statuses remain archived. A per-course file lock prevents conflicting writers. Changed input or engine creates a separate run; unchanged units may reuse verified cache entries. Resume does not fabricate completed work.

The supported model execution alternative is documented Codex non-interactive mode: https://learn.chatgpt.com/docs/non-interactive-mode . The default adapter has been exercised with real model requests. There is no assumed private Work model API. Native Work UI invocation remains distinct from executing the same local command through Codex. The personal skill and the local fallback carry exactly one folder argument, with normal local access/authentication prerequisites.

Scientific and pedagogic auditors have separate fresh contexts and cannot modify producer outputs. This provides critical role separation, not independent statistical or external scientific verification. A bounded patch pass can repair content while preserving independently solved question contracts; unresolved severe findings remain NO_GO. Actual page images are reviewed by a separate layout auditor, and technical checks execute the web interactions, numeric references, PDF rasterization and native Anki import/update. Technical PASS never sets academic_release true.

Historical references are preserved in their original locations and registered with hashes in Studio/reports/v0_4_sprint/nlp_reference_registry.json. The Gradient Descent reference distinguishes oscillation/overshooting from divergence, keeps numeric values alongside a rescaled plot, and uses Predict–Observe–Explain–Transfer. The Attention recovery reference remains CANDIDATE_NOT_APPROVED; its unfinished review is not promoted to validated evidence. v0.4 retains these cautions: a visual demo is not a proof, transfer needs explicit conditions, and baseline approval cannot be inherited after implementation changes.

Known boundaries to report: unsupported/unsafe formats and inaccessible URLs; faithful Office vector layout without a verified renderer; lossy source-image resolution; advanced mathematical typography; Basic-only Anki generation; native mobile/desktop GUI and long-term retention; unchanged-unit identity versus migration after resegmentation; arbitrary unseen-discipline excellence. The acceptance report must use PASS/FAIL/NOT_TESTED and cannot assert an actual Work UI test merely from a local CLI test.
